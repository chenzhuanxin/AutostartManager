# Windows 开机自启动管理面板

一个纯 PowerShell 写的 Windows 自启动项扫描与管理工具。扫描本机所有开机自启动项（注册表 / 启动文件夹 / 计划任务 / 系统服务），生成一个可交互的 HTML 面板，**自动标注哪些建议关闭、哪些不可关闭**，并支持安全回滚。

> **零依赖**：只用 Windows 自带的 PowerShell 5.1，不需要安装 Python、Node 或任何第三方库。整个文件夹拷到任意 Windows 10 / 11 电脑双击即用。

---

## 它解决什么问题

电脑越用越卡，开机越来越慢，很大一部分原因是各种软件偷偷把自己塞进了开机启动项。手动清理有几个痛点：

- **入口分散**：任务管理器只能看一部分，计划任务和服务要去另外的地方
- **看不懂**：满屏英文服务名，不知道哪个能关哪个不能关
- **怕关错**：关掉关键项导致系统异常，又不知道怎么恢复

这个工具把四类自启动入口**汇总到一起**，用「是否影响正常使用」为标准自动分级，并且**每次操作前自动备份、一键还原**。

## 快速开始

### 第一步：下载

```bash
git clone https://github.com/chenzhuanxin/AutostartManager.git
```

或者点仓库右上角 **Code → Download ZIP**，解压到任意位置。

> **路径要求：无。** 放在桌面、D 盘、U 盘、含中文或空格的目录（如 `D:\我的工具\自启动管理\`）都可以正常工作，脚本全部用 `$PSScriptRoot` 动态定位自身位置，**不需要修改任何路径配置**。

### 第二步：运行

双击 **`启动面板.bat`**。

流程是：弹出 UAC 提权窗口（点「是」）→ 自动扫描 → 生成面板 → 浏览器自动打开。

> **为什么要提权？** 读取计划任务和系统服务需要管理员权限，否则这两类自启动项会扫描不全。如果不想提权，可以在 PowerShell 里执行 `.\Start-Panel.ps1 -NoElevate`，仍能扫描注册表和启动文件夹。

### 第三步：选择要关闭的项

面板里：
- 「建议关闭」的项**已经帮你默认勾选**好了
- 「不可关闭」的项是**灰色锁定**的，勾不上（系统关键项，双层拦截）
- 点每行右侧的「详情」可以展开看完整程序路径、数字签名、发布者

### 第四步：执行关闭

点右下角 **「立即关闭选中项」** → 弹窗里点「复制并关闭」→ 在项目文件夹打开 PowerShell，粘贴执行。

> 浏览器出于安全限制无法直接修改系统，所以采用「面板选择 + 命令行执行」两步走。这是刻意设计，不是缺陷——它保证你在真正改动系统前，有机会看到完整的命令内容。

### 如果需要撤销

双击 **`backup\restore-last.bat`**，或者在项目根目录双击 **`恢复上次关闭项.bat`**，即可恢复最近一次关闭的所有项。

## 分级标准

工具用「**关掉之后影不影响你正常用电脑**」这一条作为判断标准：

| 等级 | 标识 | 判定依据 | 面板行为 |
|:---|:---|:---|:---|
| 🔴 **不可关闭** | 红色锁定 | 系统关键项（安全中心、硬件驱动托盘）、微软官方组件、位于 `C:\Windows` 的核心项、系统注册的卸载维护入口 | 勾选框禁用，命令行层也会拒绝执行 |
| 🔵 **建议保留** | 蓝色 | 输入法、IM、AI 助手、网银 U 盾组件、远程控制、开发环境（MySQL/phpStudy 等）、安全软件 | 可选，但不建议关 |
| 🟠 **建议关闭** | 橙色 | 自动更新器、组件预加载、浏览器后台常驻服务、剪贴板助手 | **默认勾选** |
| ⚪ **待确认** | 灰色 | 无法自动判定用途，或位于临时目录 | 需人工判断，建议先保留 |

判定综合了 **程序数字签名、安装路径、条目名称词边界匹配** 三个维度。举个实际例子：

- 名字里带 `Update` 且是第三方签名的 → 建议关闭（更新器，关了不影响使用）
- 名字里带 `Update` 但在 `C:\Windows\System32` 下且微软签名 → 建议保留（系统维护任务）
- 名字叫 `dt_app` 看着可疑，但实际是打印机服务，位于 `Program Files` → 建议保留

## 工作原理

### 扫描的四个来源

| 来源 | 注册表位置 / 说明 |
|:---|:---|
| 注册表 Run | `HKLM\...\Run`、`HKCU\...\Run`、`WOW6432Node` 32 位分支、`RunOnce` |
| 启动文件夹 | 当前用户 + 所有用户的 `Startup` 目录（含 `.lnk` 快捷方式解析） |
| 计划任务 | 只挑「登录/开机触发」且**非微软发布**的任务，避免淹没在几百个系统任务里 |
| 系统服务 | 只挑「自动启动」的**第三方**服务 |

### 关闭机制（关键设计）

**不删除、不修改原始注册表值。**

关闭注册表启动项时，工具写入的是 Windows 官方的 `StartupApproved` 禁用标志位：

```
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run
  └── 条目名 = <12 字节二进制>
       02 00 00 00 ...  = 已启用
       03 00 00 00 ...  = 已禁用
```

这与你在**任务管理器 → 启动**里点「禁用」是**完全等价**的官方机制。

为什么不用「删除注册表值」这种常见做法？因为那会让用户**彻底丢失该条目的配置**，想恢复时必须重新知道原始命令行。用 `StartupApproved` 则原始值一直都在，启用只是翻一个标志位，**随时可逆且零信息损失**。

计划任务用 `Disable-ScheduledTask`，服务用 `Set-Service -StartupType Disabled`，都是官方可逆接口。

## 常见问题

**Q：会不会把我的电脑搞坏？**

不会。三重保险：① 扫描阶段 100% 只读；② 不可关闭项在面板和命令行**两层**都被硬性拦截；③ 每次关闭前自动备份，出问题一键还原。

**Q：关掉这些会影响软件使用吗？**

「建议关闭」的都是更新器和后台常驻组件。关掉后软件**功能完全正常**，只是不再开机自动运行、不再后台自动更新。需要更新时手动打开软件即可。

**Q：面板里为什么不能直接点按钮就生效？**

浏览器的安全沙箱不允许网页修改本机系统。这是浏览器的硬限制，任何本地 HTML 工具都绕不过。所以采用「面板勾选 → 生成命令 → 你确认后执行」，反而多了一道人工复核。

**Q：可以用命令行直接操作吗？**

可以，支持脚本化：

```powershell
# 列出所有项及其 id
.\Apply-Autostart.ps1 -Action List

# 先试运行看会改什么（不实际执行）
.\Apply-Autostart.ps1 -Action Disable -Ids rk_abc123, rk_def456 -DryRun

# 实际关闭
.\Apply-Autostart.ps1 -Action Disable -Ids rk_abc123, rk_def456

# 查看所有备份
.\Apply-Autostart.ps1 -Action ListBackups

# 恢复最近一次
.\Apply-Autostart.ps1 -Action Restore

# 恢复指定备份
.\Apply-Autostart.ps1 -Action Restore -Backup .\backup\autostart-Disable-20261002-173706.json

# 重新启用某项
.\Apply-Autostart.ps1 -Action Enable -Ids rk_abc123
```

**Q：换电脑后需要改配置吗？**

不需要。这正是本项目刻意保证的——**所有脚本用 `$PSScriptRoot` 定位同级文件，没有任何硬编码的绝对路径**。整个文件夹拷到任何位置、任何电脑都能直接运行。连备份目录在脚本目录不可写时（比如放在 `Program Files`）都会自动回退到 `%LOCALAPPDATA%\AutostartManager\backup`。

## 环境要求

- Windows 10 / Windows 11（Windows 7/8 未测试）
- Windows PowerShell 5.1（系统自带，无需额外安装）
- 管理员权限（读取计划任务和服务需要；不提权仍可扫描部分内容）

---

## 注意事项

- 本工具面向**自用电脑的启动项整理**。企业域环境下的组策略启动脚本不在扫描范围内。
- 「不可关闭」的判定规则是保守策略——宁可让你少关一个，也不让你关错一个导致系统异常。
- 如果某个项你不确定，**建议先保留**。少关一个最多浪费一点开机时间，关错一个可能要花时间排查。
